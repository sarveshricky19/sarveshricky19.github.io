A little about how I work

Stay close to the problem

From the first request to the production fix

I like knowing what happens after the code ships.

I'm happiest when I can follow a problem end to end: why an API is slow, why a payment didn't reconcile, or why a support issue keeps coming back. I've moved between building features and supporting production, and both have shaped how I work.

At Yappes, I worked on the controls that help an API gateway stay useful under pressure. At BYJU'S, I worked on finance workflows where invoices, credit notes, and payments had to line up. At Delightree, I built analytics pipelines and an AI search feature using RAG.

I care about leaving a service easier to understand than I found it: tests around the behaviour, useful logs when something breaks, and a fix that makes the next incident less likely.
